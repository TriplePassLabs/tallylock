# TallyLock security review, 2026-11-12

Scope: TallyLock 0.1.0a4 source on branch `security/review-2026-11-12` of /workspace/projects/prove-build, its release chain, and the tallylock-board registry repo. Reviewer: adversarial pass focused on receipt forgery. Changes are uncommitted on the branch; nothing was pushed, tagged or published.

## Receipt forgery: what is covered and what is not

Covered, with code read and tests run:
- RFC 3161 tokens: strict DER, SHA-256 imprint equals the ledger head, signed attributes (content type, message digest, ESS signing-certificate binding), RSA 2048+ or P-256/P-384 signatures, chain to the two bundled roots, validity at genTime, critical timeStamping EKU, unknown critical extensions refused. Wrong imprint fails the ledger; other token faults show as "rejected", never as verified.
- OTS proofs: the detached header digest must equal the expected digest; bounded parsing; a Bitcoin attestation counts only when a checked header's merkle root equals the computed message.
- Online header checks: proof of work against the bundled difficulty table, links, two providers agreeing on both ends of each range, tips within one block. Past-table difficulty now capped (F1).
- Saved evidence: now floor-gated and credited only with carried headers (F1).
- Ledger: canonical lines, contiguous sequence, hash chain, every entry matched to its sealed receipt, sealed attempts missing from the ledger are refused, head proofs and tokens must match their head.
- Claim lines: every number recomputed; registry entries must claim the newest head (F2); earlier plans that disappeared are caught in repo mode.
- Board: entries are reverified at build time; text no longer claims unchecked Bitcoin blocks or unsigned service names (F3, F5); all fields HTML-escaped; links restricted to http and https.

Not covered:
- Anchors from an author-supplied chain cache (F7) and the residual cost of saved evidence (F12).
- Hidden attempts: tail truncation, fresh repos, many near-identical plans (F8). Scores, logs and model identity are self-reported.
- A compromised or mis-issuing TSA under a bundled root, and TSA key compromise after revocation (F10).
- Full Bitcoin consensus, and two providers lying together.
- 32-bit claim-line prefixes (F9).

## Supply chain

- release.yml: tag-triggered, `permissions: {}` at the top, build job `contents: read`, publish job `id-token: write` in environment `pypi` via trusted publishing, every action pinned by SHA, `persist-credentials: false`, no `pull_request_target`, no untrusted input in `run:` steps. Weakness: unpinned build tools (F11). GitHub environment protection rules could not be checked from the repo.
- ci.yml: `push` and `pull_request` only, `contents: read`.
- Runtime dependencies are pinned with `==` (no hashes); jsonschema's transitive dependencies float.
- sdist: MANIFEST prunes .planning, .superpowers, .worker, .venv, dist and build. It ships PLAN.md, RUNBOOK.md and docs plans; a grep of tracked files for private paths, internal IPs, host names and personal emails found nothing. Checked against the local 0.1.0a1 dist and MANIFEST.in, not the 0.1.0a4 file on PyPI.
- Git history of prove (all refs) and tallylock-board: no tokens, keys, private host paths, internal IPs or personal emails. Only synthetic test secrets. Commits use a GitHub noreply address.
- Network: default TLS context, no redirects followed, response caps and deadlines. DigiCert's TSA is plain HTTP, which is acceptable because the token is signed and fully checked.
- Untrusted input: the Inspect adapter reads zip members in memory with per-member and total caps and never extracts; adapters parse JSON through a bounded parser; bundles refuse links and non-regular files.
