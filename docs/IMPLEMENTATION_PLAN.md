# Standalone TallyLock CLI implementation plan

> For agentic workers: use subagent-driven-development with bounded owned files, test-first changes and independent review. This plan implements the reviewed PLAN.md and Chris's explicit standalone-product clarification.

Goal: an independently installable generic CLI candidate that ordinary external evaluators can use, with auditable receipt guarantees, a real OpenTimestamps path, safe offline verification and documented external-testing feedback.

Architecture: separate canonical data/Merkle primitives, versioned contract validation, safe local persistence, read-only verification, timestamp/network transport, optional imports and CLI presentation. No Colony/Ouroboros runtime dependency. Primary path uses generic artifact directories; optional normalized traces provide more detail. Harness adapters are data converters only.

Tech stack: Python 3.11-3.13/Linux first, setuptools packaging, RFC8785 library, upstream OpenTimestamps library, standard-library CLI and unittest/pytest. Wheel/source installs must work outside the repo. Keep verifiers free of model SDKs and live service calls.

## Global constraints

- Product name TallyLock; provisional distribution tallylock; console tallylock plus python -m tallylock (renamed from prove on 2026-11-07, which collided with Perl's /usr/bin/prove) to avoid an unrelated executable on PATH.
- Unsigned identity and execution claims always unverified. Integrity, membership, timestamps and scoring are separate report fields.
- Full anchored verification needs externally supplied verifier-trusted validated-node cache. Explorer headers and test-generated evidence are never mislabeled independently validated.
- Frozen canonical cores and receipt IDs never change during proof upgrades. Atomic persistence, one writer, safe recovery and hostile filesystem handling are required.
- Builds and batch tests use the capped external worker, not this editor container. No GPU, model inference, lab experiment or family-service changes.
- Workers own only assigned modules/tests, do not revert others, and do not mutate services or secrets. Main session owns architecture, integration, external submissions and final acceptance.

### Task 3: Descriptor-safe storage primitives

This task addresses race conditions, TOCTOU filesystem attacks and concurrent process locking; it requires security/correctness reasoning, not mechanical filesystem wrappers.

Ownership: create/edit only `/workspace/projects/prove-build/src/tallylock/filesystem.py` and `/workspace/projects/prove-build/tests/test_filesystem.py`. You are not alone; preserve all other files. Consume schema.validate_artifact_path/validate_inventory_paths and TallyLockError; no receipt, scorer or network implementation in this task. Later store/verifier modules must reuse this boundary rather than reimplement unsafe Path.read_bytes calls on untrusted receipt content. Use `bash .planning/worker.sh test tests/test_filesystem.py` for RED/GREEN and cumulative tests in the capped worker; no batch work in the editor, no services, secrets or subagents. Do not commit; main reviews and commits owned files.

Required interface: `Directory(root: Path)` context manager, `.fd` read-only opened-root descriptor property valid only inside that context; `list_files(prefix: str='')->list[str]`; `read(path: str, limit: int=8388608)->bytes`; `digest(path: str)->tuple[str,int]`; `mkdirs(path: str)->None`; `copy_file_to(path: str, destination: Directory, destination_path: str)->tuple[str,int]`; `atomic_write(path: str, data: bytes, replace: bool=False)->None`; and `WriterLock(directory: Directory)` context manager plus `recover_lock(directory: Directory, expected_sha256: str)->None`. Directory opening requires an existing root and never creates it implicitly. Return list paths relative to root, UTF8-byte sorted. Invalid paths/types/conflicts use TallyLockError code2; operational I/O failures use code5; unsupported required primitives use code4. Reads of zero bytes/empty files are valid.

Root and every ancestor below it use descriptor-relative O_DIRECTORY/O_NOFOLLOW traversal. Open candidate files nonblockingly before fstat, so FIFOs cannot hang before type validation. Reject every nonregular file, links and path collisions; stream hashes/copies in bounded chunks and compare descriptor metadata and no-follow re-opened path identity after reading. Non-mutating read operations never create directories. Writers create parents safely beneath the opened destination root. atomic_write uses fsynced private temporary files, no-clobber publication by default and directory fsync; replace is explicit and used only for mutable state/proofs. copy_file_to also publishes a fully streamed/fsynced private temporary file atomically with no-clobber, never a partial final file on ordinary exceptions. Always preserve an existing immutable destination even across races. Clean only temporary files owned by the current operation. The trusted store layer may use .fd for narrowly controlled constant-name staging directory publication; arbitrary receipt paths still go through these helpers.

WriterLock creates .prove/lock exclusively, holds an OS flock for its lifetime and records a random ownership token/PID/time as local-only metadata. After acquiring flock and writing metadata, recheck that its inode is still reachable at the lock path before entering the critical section (closes create-before-flock vs empty-file recovery races). Release deletes only its own unchanged lock. Recovery explicitly matches the observed lock-file SHA256, obtains a nonblocking OS lock and verifies path identity before unlinking; never evict a live writer or delete by guessed PID liveness. Stale empty files must be recoverable by their observed digest. Bound lock metadata reads at64KiB. No credentials, global services, inference or unsafe recursive deletion.

#### Task 4a: Pure normalized-record engine

Implement this bounded slice before store/fixture persistence. Interfaces:

- `schema.EventValidator(manifest, attempt_id)` validates and snapshots the supplied manifest once. Its `validate(event)->dict` returns the original event after the same shape/direct-binding checks as `validate_event`. Freeze a defensive canonical copy of the manifest, registration ID and sample membership set. Subsequent caller mutation cannot alter its bindings. `validate_event` remains the one-shot equivalent. Repeated events must not revalidate or rehash the entire manifest.
- `schema.validate_inventory(value)->dict` validates a canonical object with exact inventory-entry shapes using the existing packaged inventoryEntry definition and path/collision rules. Return the original value. Reuse this in validate_result and records.build; do not duplicate a weaker entry validator or require a synthetic result merely to validate an inventory.
- `records.decode(data: bytes, *, require_canonical: bool=True)->list[dict]` parses bounded JSONL. Empty bytes mean zero events. Require a final LF for nonempty input and reject BOM, CRLF, blank lines, duplicate keys, invalid UTF8, non-object events and per-event/total limits (1MiB event excluding LF,64MiB total including delimiters). With the default, require exact canonical bytes on every line. The explicit import mode accepts ordinary JSON whitespace/key order inside a line, without weakening JSON/value/size rules. It never repairs malformed records or invents fields.
- `records.encode(events: list[dict])->bytes` emits canonical event bytes plus LF, enforces the same limits and excludes non-object records. It does not claim lifecycle validation by itself.
- `records.build(manifest, attempt_id, inventory, outcome, reason, *, events: list[dict]|None=None)->RecordSet` validates immutable inputs and whole-record consistency. Artifacts mode requires events=None and deterministically generates inventory events in UTF8 path order followed by attempt_end. Trace mode requires an explicit event list (including an explicitly empty list for failure before logging), preserves its order, and never silently appends terminal records or corrects outcomes. Use the prepared event validator and membership sets/dicts for linear trace processing.
- `records.check(manifest, result, data: bytes)->RecordSet` first validates the manifest/result and canonical stored records, then verifies every declared records metadata field, resource totals, lifecycle and budget consistency. It must reject a correctly hashed but contradictory trace.
- `RecordSet` is a frozen dataclass with fields `data:bytes`, `events:tuple[dict,...]`, `metadata:dict` (the exact result.records mapping), `resources:dict`, `coverage:dict`, `known_usage:dict`, and `budget:str`. Returned event/core objects are defensive copies. Metadata includes path, raw SHA256, byte count, count, tree algorithm and root. Coverage is `{state, expected, started, ended}`; artifacts mode uses state `not_applicable` with null counts, trace uses `complete` or `incomplete` and integer counts. Coverage counts terminal samples regardless of terminal success status, and never asserts honest execution. `known_usage` gives trace lower bounds for calls and each usage field; all null for artifacts. Budget is `not_declared`, `exceeded`, `unknown`, or `recorded_within` as defined in the protocol.

Whole-trace checks include contiguous indices, direct manifest/attempt bindings, starts/ends, globally unique call IDs, backward same-sample retries, no calls outside open samples, inventory references, exact final outcome/reason, completed coverage and explicit unsuccessful empty traces. Enforce safe-integer bounds on derived counters, including known subtotals with unknown fields. Known exceeded budgets require the declared budget_exceeded outcome even if another call omits usage. For a declared ceiling, complete recorded totals below/equal it permit recorded_within; any unknown constrained total makes compliance unknown unless a known lower bound already exceeds. No ceilings yields not_declared. A budget_exceeded outcome can reflect unrecorded information, so it need not fabricate a measured excess.

Add meaningful failing tests for exact encoding, altered raw hash/length/root/count/resource values, malformed JSONL/boundaries, valid/invalid artifact ordering, all lifecycle and retry contradictions, failed/empty traces, usage/null/zero and aggregate overflow, known lower-bound violations, prepared-manifest mutation and validate-once behavior. Run RED/GREEN and cumulative checks only through `.planning/worker.sh`. Main independently reviews and reruns; no worker commit.
